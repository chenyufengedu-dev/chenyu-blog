# Cyber Office 理想整页设计蓝图（喂给设计 AI 用）

> 用途：把 Cyber Office **全部做完后的理想形态**整理成一份设计 brief，交给网页端设计 AI 出高保真设计图。之后我们按图构建。
> 这不是当前实现现状，而是"终态目标"。设计红线**必须遵守**（见文末），否则生成图会偏 AI 感、跟全站不协调。

---

## 一、这个页面是什么（一句话）

一个嵌在个人博客里的**「多 Agent 协作实验室」**：用户给一个议题，多个 AI 角色（产品经理 / 前端 / 生信研究员 / 审稿人等）围坐俯视像素圆桌，由一个**主持人 Agent 动态调度**轮流发言、互相质疑，最后由总结 Agent 产出结论。核心不是"聊天"，而是**展示一套真实的多 Agent 编排系统在运转**。

## 二、想给观看者的印象（设计要服务于此）

1. **"这是个调度系统，不是循环调 5 次 API。"**（最重要——编排要被看见）
2. 精致、克制、专业——像 Linear / Stripe 的产品页，不是花哨的 demo。
3. 有生命力的像素小场景，但外壳 UI 极简留白。

## 三、页面结构（从上到下的区块）

> 桌面优先。整体单列居中，最大宽度约 `860–960px`，留白充足。

### 0. 页面标题区
- 主标题 + 一句副标题（说清"这是什么、能得到什么"，**不要**用 `DeepSeek`/`SSE` 这类技术黑话）。
- 可选：一行小字点明"这是一个多 Agent 编排的演示项目"。

### 1. 入口 / 控制区（清晰区分两种模式）
- **两个层级分明的入口**：
  - 「▶ 看一场演示会议」——播放预生成的样本会议（默认、零成本、样本模式下**锁定/隐藏议题输入框**）。
  - 「✎ 用我的议题开一场」——用户输入议题，实时跑真实会议（受限流保护）。
- 3 个**可点击的示例议题**（点了直接填入），降低"不知道输入什么"的门槛。
- 播放中：暂停 / 继续 / 重新开始 控件。

### 2. 会议进度状态条
- 一条轻量状态：`讨论中 · 第 3/5 轮 · 当前发言：产品经理`。
- 体现阶段推进（讨论 → 质疑 → 总结），结束时明确显示 **"会议完成 ✓"**。

### 3. 舞台区（视觉主体）——像素圆桌会议室
- 3/4 俯视会议室：背景 + 圆桌 + 5 个像素角色围坐 + 桌面道具 + 角落一只可点互动的像素猫。
- **发言者高亮**：当前发言者全彩、身后暖光聚光、头顶小气泡；其余人压暗降饱和。
- 近大远小的真实围坐感（不是一排贴墙）。
- **这块是"特许像素破例区"**，可以有像素画的生动感；但它外面的所有 UI 外壳仍守红线。

### 4. 字幕条（唯一一处）
- 舞台正下方**一条**字幕，始终显示"谁在说 + 说什么"，带发言者名字（橙色）。
- 打字机逐字效果，**点击一次可跳过直接显示整段**。
- 像素/等宽风格的名字标签，字幕正文正常易读（行高 ≥1.7）。

### 5. ⭐ 编排逻辑面板（作品集核心，可折叠开关）
> 评审原话："这一个开关的加分大于所有动画之和。" 这是本页最想被看见的东西。

一个「查看编排逻辑」开关，展开后显示两部分：

- **上半：编排流程图**——一张清晰的流程/状态图，随会议实时**高亮当前所处阶段**：
  ```
  主持人调度 → 点名某角色 → 角色发言 → 回到主持人（循环 N 轮） → 总结 Agent 收口
  ```
  当前走到哪一步，哪个节点亮起（橙色）。
- **下半：主持人本轮决策**——展示主持人这一轮真实输出的**结构化 JSON**，例如：
  ```json
  { "action": "call_on", "speaker": "reviewer",
    "hostText": "请审稿人挑战一下这个方案",
    "prompt": "从统计严谨性角度质疑前面的结论" }
  ```
  让观看者亲眼看到"主持人在用结构化输出做动态调度决策"。

### 6. 发言记录 / Transcript（可折叠）
- 常驻可折叠的完整发言记录（谁、第几轮、说了什么），支持回看。

### 7. 结论区
- 会议结束后，总结 Agent 的结论以清晰卡片呈现，有"收束感"（像纪要落到桌上）。
- 结论**可复制 / 导出 Markdown**。

### 8. 收尾：编排回顾（可选彩蛋）
- 一句小结：`本次 6 轮 · 调用角色 [pm×2, bio×1, reviewer×2] · 主持人 3 次动态改变了发言顺序`，佐证"动态调度真的发生了"。

## 四、关键状态（设计图请覆盖）

- **待机 / 未开始**：入口 + 示例议题，舞台静态。
- **播放 / 发言中**：高亮发言者 + 字幕 + 进度条走动 + 编排面板节点点亮。
- **思考 / 等待中**："XXX 正在思考…" 的等待态（实时会议 API 慢时不能是僵住的静止画）。
- **错误 / 重试**：友好错误提示 + 重试按钮。
- **会议完成**：结论卡片 + 编排回顾。

---

## 五、设计红线（生成图必须遵守，务必写进给 AI 的提示）

1. **唯一强调色 `#ea580c`（橙）**，不引入其他鲜艳色；不用彩色渐变、不用渐变文字。
2. **不用大面积渐变背景**、不用 AI 感标签云、不堆砌动效。
3. 圆角最大 8px（`rounded-lg`），**不用 pill 胶囊卡片**。
4. 正文行高 ≥ 1.7；字重不超过 600（semibold），无超粗标题。
5. **深色 / 浅色两套都要出**。
6. 气质锚点：**Linear 的精致 + Stripe 的浅色专业 + Apple 的极简留白**。
7. 唯一例外：舞台区的**像素小人/像素场景**允许生动的像素画风；但它之外的所有 UI 外壳（按钮、面板、字幕框、进度条、编排面板）仍严格守以上红线。

> 一句话给设计 AI 的风格锚：**"克制、专业、留白充足的产品页，唯一橙色强调，圆角≤8px，无渐变；中央嵌一块生动的 3/4 俯视像素会议室场景。深浅两版。"**
