# Cyber Office 体验优化路线图（基于产品访谈）

> 性质：**产品方案 + 推进节奏**。回答两个问题：要做成什么样、一个人该按什么顺序做。
> 来源：2026-08-15 三轮产品访谈（定位 / 落差 / 取舍）。

---

## 一、需求还原

### 定位
**体验娱乐属性 + 作品集属性**，工具属性弱（"真正用于干活的情况比较少"）。
→ 推论：**好看和好玩优先于好用**。不要为"工具价值"做功能。

### 北极星：一条三段情绪曲线
```
第一眼「这个挺好看啊，很惊艳」 → 看下去「这个有意思」 → 回味「这机制做得很专业」
```
→ 推论：**视觉是入口，内容是留存，技术是回味**。编排面板虽然技术含量最高，但它排第三，不该抢在视觉前面投入。

### 期望使用姿势
愿意**完整体验一场**并了解背后机制；不要求真的当工具用。
→ 推论：一场会议要有**完整的起承转合和收束感**，时长控制在几分钟内。

---

## 二、问题诊断：所有抱怨收敛到两个根因

### 根因 A：美术是"多张独立 PNG 叠加"的架构

现状 = 背景图 + 桌子图 + 5 张角色 PNG，各自独立缩放、各自的绘制来源与光影。由此产生的全部症状：

| 用户原话 | 技术原因 |
|---|---|
| "只是在播放图片，没有真实动作的流畅感" | 每个角色只有 2–3 帧动作切图 |
| "像几张图片重叠了一样" | 各图层光影/透视/笔触不统一，没有共同环境光 |
| "场景太死" | 背景是静止图，无环境动效 |
| "发言者切换瞬间卡顿" | 换图时才加载，且切换无过渡 |

**这不是调参数能解决的，是美术管线本身的问题。**

### 根因 B：编排是"严格轮流独白"

现状 = `主持人点名 → 一个人讲完 → 主持人点名 → 一个人讲完`。由此产生：

| 用户原话 | 技术原因 |
|---|---|
| "发言内容像 AI" | 角色 prompt 太薄，没有鲜明立场与说话风格 |
| "听众没有反应" | 非发言者无任何状态变化（属表现层，见根因 A） |
| "节奏太规整" | 编排强制每轮一人、发言长度上限统一（160 token） |
| "没有情绪起伏" | 不允许打断、反驳、连续发言 |

**这四条是同一个病。**

## 三、关键区分：两种"卡顿"，方向相反

> ⚠️ 这条决定了施工顺序，务必先看懂。

| 类型 | 表现 | 解法 | 加帧的影响 |
|---|---|---|---|
| **动作跳跃** | 动作一抽一抽、像翻页 | 增加帧数 | ✅ 变好 |
| **加载闪烁** | 换帧/换人瞬间闪一下、卡一下 | 预加载 + 合并成一张图 | ❌ **更糟**（帧越多，散图越多） |

现在两种同时存在。**所以必须先修"加载闪烁"，再去加帧**——否则辛苦做的几十帧动画会比现在更卡。

## 四、视觉路线决策：AI 生成视频 → 切帧 → 序列帧

采纳 Chenyu 提出的方案。评估如下。

### 为什么可行
- 能一次拿到**十几到几十帧的连续动作**，动作质感相比现在 2–3 帧是质变；
- 保留"具象小人开会"的可爱感（抽象化方案会丢掉这个）；
- 相比"代码驱动骨骼动画"，不需要重做角色结构（Chenyu 试过、认为会卡）。

### 必须防住的四个风险

1. **帧间漂移（最大风险）**：AI 视频每帧的角色会有细微形变，做成循环会"抖"。
   → 对策：**只从同一段视频里挑帧**，绝不跨视频拼；动作幅度限制在上半身小幅度（坐姿、点头、手部小动作），大动作必漂。

2. **抠像困难**：视频抠背景比单图更难保持边缘一致。
   → 对策：生成时就要求**纯色/绿幕背景 + 固定机位 + 角色位置不动**。沿用现有 `scripts/split-poses.mjs` 的绿幕键出逻辑。

3. **体积与加载**：几十帧散图 = 几十个网络请求，直接引发"加载闪烁"。
   → 对策：**合并成一张 sprite sheet**（雪碧图），用 CSS `background-position` 切帧。一个角色一次请求，彻底消灭闪烁。

4. **帧率误区**：不是越多越好。
   → 对策：目标 **8–12 帧、10–12fps 定格播放**。低帧率定格正是像素/复古质感的来源；平滑补间反而显廉价。

### 循环点
首尾帧必须能衔接，否则每次循环会跳一下。挑帧时优先选"动作起点=终点"的片段（如：手放下 → 抬起 → 放下）。

## 五、推进路线（主线 + 支线）

> 面向"一个人、慢慢推进"设计：每个阶段都**独立可见效果**、可单独提交、不做到一半卡住。

### 主线（视觉）

**阶段 V0 · 止损：先修真卡顿**（成本最低，立刻见效）
不动任何美术资产，解决技术性卡顿：
- 所有角色帧**预加载**，消灭首次切换的闪烁；
- 发言者切换加**过渡**（当前是硬切）；
- 打字机节奏优化：标点停顿更久、字间微随机延迟，去掉机械感。

*验收*：连续播放样本会议，换人、换帧不再有闪烁或跳变。

**阶段 V1 · 一个角色的垂直样本**（验证路线，别一上来铺全量）
挑 **1 个角色**（建议 `pm` 或 `host`）走完整流程：AI 出视频 → 切帧 → 挑 8–12 帧 → 合成 sprite sheet → 接进页面。
- 只做两套循环：`待机` + `说话`；
- 目标是**证明这条路能出精致感**。

*验收*：这一个角色明显比其余四个"活"。不达标就调整出图方式，**不要往下铺**。

**阶段 V2 · 铺开到全部角色**
V1 验证通过后，把流程套到其余 4 个角色。可以一次做一个，做完一个上线一个。

**阶段 V3 · 场景精致化**
解决"像几张图片重叠"：统一光影（给所有图层加一层共同的环境光/色调蒙版）、窗外光线缓慢变化、植物/窗帘微动、发言者聚光更明确。

### 插入项（走查后新增）

**B1 · 气泡化**（教程：[`plans/2026-08-16-cyber-office-speech-bubbles.md`](../plans/2026-08-16-cyber-office-speech-bubbles.md)）
发言从"下方字幕条"搬回"角色头顶气泡"。起因：字幕在舞台下方几百像素处，用户本能读字，导致**角色动画根本没人看**。附带把发言缩短到 35 字、轮数从 4 提到 8。

**B2 · 结论方案化**
**产品原则：一场不出方案的讨论在体验上是失败的**——起承转合缺了"合"。现在的总结提示词是通用模板（核心结论/大纲/行动），要改成针对具体问题产出真正的方案：问题拆解、分歧点、权衡、具体做法、先做什么。

### 支线（内容，随时可插，与美术互不干扰）

**阶段 C1 · 内容层真人感**（纯提示词，成本极低、见效最快）
- 每个角色写鲜明人设：说话风格、口头禅、固定立场与偏见；
- 允许**直接点名反驳上一个人**（"我不同意前端刚才说的……"）；
- 发言长度**不再统一**：允许短到一句话的插话，也允许一次讲透；
- 主持人**少说话**，只在跑题或该收口时才出声。

*验收*：五个角色的发言，遮住名字也能猜出是谁说的。

**阶段 C2 · 节奏层真人感**（改编排逻辑）
- 允许主持人**连续点同一个人**（追问）；
- 允许"反驳"作为一种独立的调度动作；
- 一场会议里制造一次明确的**分歧点**，再收敛。

### 交互（按 Chenyu 排的优先级，穿插在后期）

1. **会后追问某个角色**（第一优先，实现最安全，不打断主体验）
2. **会中举手提问**
3. **观众式把玩**（点角色看人设、点道具、逗猫）
4. ~~会前选阵容、设定性格~~ —— **暂不做**。工作量大、对整体流程作用小（Chenyu 判断）。

### 已决定不做
- ❌ **逐轮审批（原 S5）**：把观众变成操纵木偶的人，破坏"专家自主讨论"的核心体验。教程已写但不执行。

## 六、现在开始做什么

**第一件事：阶段 V0（止损）。**

理由：
1. 它直接命中你说的三处卡顿（角色动作、打字机、发言者切换）；
2. 成本最低，一个下午能看到效果；
3. **它是 V1 的前置**——不先修加载闪烁，做再多帧也会更卡。

V0 完成后，同时开两条线：
- 你去尝试 **V1 的出图流程**（AI 视频 → 切帧），拿一个角色试水；
- 我同时给 **C1 的提示词优化**，这条完全不依赖美术，可以立刻改善"内容像 AI"。

## 七、判断依据备忘

- 视觉排在内容之前，是因为北极星第一段是"好看"。但 C1 是例外：它成本太低、见效太快，值得插队并行。
- 不做"会前设定阵容"：投入产出比最差。
- 编排面板（技术展示）已经完成，排在北极星第三段，**不再追加投入**。
